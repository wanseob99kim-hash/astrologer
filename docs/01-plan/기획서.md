# 베딕 점성술 서비스 기획서

> 인도 전통 점성술(Jyotish / 죠티쉬)을 한국 대중 대상 웹 서비스로 만든다.
> 벤치마크: horasat.sowonary.com (태국 점성술, 프루퍼 주식회사)

작성일: 2026-09-03
상태: 초안 (Plan)

---

## 1. 한 줄 정의

**생년월일만 넣으면 나의 수호 행성이 나오고, 시간·장소를 더하면 27개 탄생별(나크샤트라)까지 확정되며, 연인과는 인도 전통 36점 궁합으로 이어지는 무료 운세 서비스.**

## 2. 왜 지금, 왜 인도인가

### 2.1 시장 공백

- 사주: 포화. 차별화 불가
- 서양 별자리: 포화. 12종뿐이라 얕음
- 태국 점성술: 최근 유튜브발 유행. 벤치마크 사이트가 선점
- **베딕(인도): 공급 거의 없음.** 레이디경향 주간 연재, 개인 블로그·스레드 수준. "한국에서 베딕 다루는 분 잘 못 봤다"는 반응이 확인됨

### 2.2 재료 우위 (vs 태국)

| 항목 | 태국 | 인도 | 우위 |
|---|---|---|---|
| 유형 수 | 8요일 → 24종 | 27 나크샤트라 (×4 파다 = 108종까지 확장 가능) | 인도 |
| 인생 흐름 | 타크사 (개략) | 빔쇼타리 다샤 120년, 대운/소운 2단계 | 인도 |
| 궁합 | **해시 기반 가짜 점수** (58~99점 고정 범위) | **아쉬타쿠타 36점 = 실제 전통 계산식** | 인도 |
| 결함/처방 서사 | 없음 | 도샤(나디·바쿠트) + 해소법 = 결제 명분 | 인도 |
| 도상 자산 | 요일 불상 8개 | 나크샤트라 상징 27 + 나바그라하 9 + 얀트라/라트나 | 인도 |
| 진입 장벽 | 요일 계산만 (계산 0) | 달 위치 = 천체 계산 필요 | **태국** |

→ 유일한 열세인 "진입 장벽"을 하이브리드 퍼널로 무력화하는 것이 이 기획의 핵심.

## 3. 핵심 설계: 3단 하이브리드 퍼널

벤치마크의 약점은 **무료 결과 → 갑자기 1,900원 결제**로 계단이 하나뿐인 것.
우리는 계단을 여러 개로 쪼개 각 단계마다 사용자 투입(input)을 늘리고 즉시 보상을 준다.

```
L0  무료 · 계산 없음 · 30초
    입력: 생년월일 8자리 (+닉네임 선택)
    계산: 물랑크(일 자릿수 합) + 바갼크(전체 자릿수 합) + 요일
    출력: 나의 수호 행성 = 나바그라하 9종 중 하나
    목적: 이탈 없는 첫 보상. 공유 훅.
         ↓
L1  무료 · 천체 계산 · 추가 입력 요구
    입력: + 태어난 시간, 태어난 장소
    계산: 라히리 아야남샤 보정 → 달 황경 → 27 나크샤트라 확정
    출력: 나의 탄생별 27종 + 신격/상징/가나/요니/나디 + 다샤 시작점
    목적: 정통성 확보. 리드 퀄리파이(시간까지 넣은 사람 = 결제 의향 높음).
         ↓
L2  유료 A · 개인 상품
    상품: 빔쇼타리 다샤 인생 리포트
    출력: 120년 타임라인, 현재 대운/소운, 전성기·주의 구간, 처방
         ↓
L3  유료 B · 커플 상품
    상품: 아쉬타쿠타 36점 궁합 상세 리포트
    출력: 8쿠타 점수판, 도샤 진단, 해소 처방, 얀트라 이미지
```

### 3.1 유형이 "바뀌지" 않게 하는 원칙

L0의 그라하와 L1의 나크샤트라는 **경쟁 관계가 아니라 층(layer)이다.**
결과를 덮어쓰지 않고 쌓는다. 최종 정체성은 조합으로 표기한다.

> 예) **수리야 × 붉은 수레(로히니)**

"내 유형이 바뀌었다"는 혼란을 원천 차단한다. L0 결과는 그 자체로 완결된 콘텐츠여야 한다.

### 3.2 단계별 노출 제한 (P2 실측 근거)

출생시각 민감도 측정 결과([P2 검증보고서](../03-analysis/P2-계산엔진-검증보고서.md) §6)에 따라
각 산출물을 노출할 수 있는 단계가 정해진다. **이 선을 넘으면 안 된다.**

| 산출물 | 시간 모름 시 오류율 | 노출 가능 단계 |
|---|---|---|
| 물랑크 · 바갼크 | 0% (생년월일만으로 확정) | **L0** |
| 달 나크샤트라 27종 | 23.0% | **L1 전용** |
| 다샤 타임라인 | 23.0% | **L1 전용** |
| 파다 세분(108종) | 69.0% | L1 중에서도 **시간 정확 입력자 한정** |
| 상승궁(라크나) 기반 콘텐츠 | 90.3% | **L1 전용** + 시간 오차 경고 병기 |

- L0 화면에서 나크샤트라를 **확정 표기하지 않는다.** 티저로만 언급한다.
- 나크샤트라는 ±30분 오차에도 2.3%만 바뀌어 견고하다. 메인 정체성으로 유지한다.
- 상승궁은 ±2시간 오차에 90.3%가 바뀐다. "시간 모름" 사용자에게는 아예 제공하지 않는다.

## 5. 궁합 = 최대 차별점

### 5.1 아쉬타쿠타 36점

| 쿠타 | 배점 | 측정 | 한국형 표기(안) |
|---|---|---|---|
| Varna | 1 | 정신적 지향 | **결의 층** ※카스트 용어 삭제 |
| Vashya | 2 | 끌림·주도권 | 이끌림 |
| Tara | 3 | 별 간 거리 → 건강·운 | 별자리 거리 |
| Yoni | 4 | 본능적 궁합 (14종 동물) | 본능 |
| Graha Maitri | 5 | 지배행성 친구·적 관계 | 행성 우정 |
| Gana | 6 | 기질 (데바/마누샤/락샤사) | 기질 |
| Bhakoot | 7 | 번영·안정 | 살림 |
| Nadi | 8 | 체질·기운 | 기운 |

해석 구간: 18점 미만 비추 / 18~24 무난 / 25~32 좋음 / 33~36 최상

### 5.2 도샤(결함)와 해소 — 결제 명분의 핵심

- **나디 도샤**: 양쪽 나디가 같을 때
- **바쿠트 도샤**: 달 별자리가 6-8, 2-12, 5-9 관계일 때 (6-8이 가장 무거움)
- 전통에 **해소(캔슬) 규칙**이 존재 → "문제 발견 → 처방" 서사가 자연 발생

벤치마크는 "1,900원 내면 지표 6종을 보여줌"이 전부다.
우리는 **"당신들은 기운(나디) 구간이 겹칩니다. 전통 해소법은 이것입니다"** 를 판다. 결제 이유가 질적으로 다르다.

### 5.3 궁합 구현 시 확정 방침 (P2 실측 근거)

| 항목 | 방침 | 근거 |
|---|---|---|
| **망갈(Manglik) 도샤** | **제품에서 제외.** 넣으려면 고전 엄격 규칙(라그나 기준 1·4·7·8·12궁)으로 자체 구현 | 라이브러리 기본 규칙은 검출률 **70.3%**. 10명 중 7명에게 뜨는 경고는 정보가 아니라 소음 |
| **판정 문구** | 라이브러리 `verdict` **사용 금지.** 점수 구간(18/25/33)으로 자체 작성 | 점수 18점 이상인데 "Mismatch" 판정이 **27%** — 망갈 도샤가 점수를 덮어씀 |
| **남/녀 역할** | **양방향 계산 후 평균.** 성별 입력 받지 않음 | 아쉬타쿠타는 전통상 비대칭. 순서 바꾸면 **69%**의 커플에서 점수가 달라짐(최대 2점). 동성 커플 배제 방지 |
| **점수 신뢰도** | 낮은 점수를 숨기지 않는다 | 0~36 전 구간에 고르게 분포. 벤치마크의 해시 방식(58~99점 고정)과 달리 **낮게도 나온다는 점이 신뢰의 근거** |

- 아야남샤: **라히리(Lahiri / Chitrapaksha)** 고정. 인도 정부 공식 표준. 라이브러리 기본값 그대로 사용 가능
- 계산은 **서버 사이드**에서 수행 (SEO + 로직 은닉)
- **주의**: `panchangam-js` 는 내부적으로 `astronomy-engine` 에 의존한다.
  따라서 astronomy-engine 기반 자체 계산은 달 위치에 대해 독립 검증이 되지 않는다.
  달 위치까지 독립인 대조 상대는 의존성이 하나도 없는 `mhah-panchang` 뿐이다.
- 검증 하네스는 `engine/` 에 있다. `npm run verify` 로 언제든 재현 가능.
  라이브러리 버전을 올릴 때 반드시 먼저 돌린다.

### 8.2 앱

- Next.js 15 App Router + TypeScript (SSR 필수 — SEO가 유입의 축)
- **Tailwind 미사용.** 디자인 토큰 기반 순수 CSS(app/globals.css) 로 구현했다.
  화면 수가 적고 도상이 특수해 유틸리티 클래스보다 토큰이 유리하다고 판단했다.
- 결제: 페이앱(PayApp) 또는 토스페이먼츠 — 회원가입 없이 휴대폰 번호 기반
- 데이터: 27종/9종 콘텐츠는 코드 내 TS 상수 (DB 불필요). 결제·열람 이력만 DB

### 8.3 SEO

- FAQPage / Article JSON-LD (벤치마크가 쓴 수법 그대로 + 확장)
- `/compare/saju`, `/tradition/*` 를 롱테일 유입구로
- **sitemap.xml 도메인 실주소 확인 필수** — 벤치마크는 여기서 실수함 (Lovable 개발 도메인 `thai-fortune-buddy.lovable.app` 이 그대로 노출 중)
